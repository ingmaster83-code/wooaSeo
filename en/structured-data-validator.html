Structured Data (JSON-LD) Validator

Paste JSON-LD, or HTML containing it, to check JSON syntax, @context, required and recommended properties per type (Article, Product, Offer, FAQPage, BreadcrumbList, Organization, LocalBusiness, Event, Recipe, VideoObject, JobPosting ...), ISO 8601 dates, numeric prices, currency codes, absolute URLs and duplicate @ids. Nested entities are listed with their paths.

Example

⛔ 4 error(s), 11 warning(s) - 8 entity(ies)

Input — JSON-LD or HTML containing structured data

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {"@type": "Organization", "@id": "https://example.com/#org", "name": "Example Inc.", "url": "https://example.com/", "logo": "https://example.com/logo.png"},
    {"@type": "Product", "name": "Wireless Mouse", "image": ["https://example.com/mouse.jpg"], "description": "Quiet wireless mouse.",
     "offers": {"@type": "Offer", "price": "29.90", "priceCurrency": "USD", "availability": "https://schema.org/InStock", "url": "https://example.com/mouse"},
     "aggregateRating": {"@type": "AggregateRating", "ratingValue": "4.6", "reviewCount": "128"}},
    {"@type": "FAQPage", "mainEntity": [{"@type": "Question", "name": "Is it Bluetooth?", "acceptedAnswer": {"@type": "Answer"}}]},
    {"@type": "BlogPosting", "headline": "Launch", "datePublished": "2026-13-45", "author": "Kim"}
  ]
}
</script>

What this tool does

Check markup aimed at rich results before you deploy it. Your markup is not uploaded.

  • Input: raw JSON-LD, or HTML with several <script type="application/ld+json"> blocks
  • Syntax: JSON error location with a trailing-comma hint, missing or non-schema.org @context, @graph and nested entity traversal
  • Type rules: Article / BlogPosting, Product / Offer / AggregateRating / Review, FAQPage / Question / Answer, BreadcrumbList, Organization, LocalBusiness, Person, WebSite, Event, Recipe, VideoObject, HowTo, JobPosting, Course, SoftwareApplication and more
  • Value formats: ISO 8601 dates (including impossible dates), numeric prices, ISO 4217 currencies, absolute URLs, standard availability values and rating ranges
  • References: duplicate @id and undefined @id references

💡 Tips

  • Write prices as plain numbers such as "29.90" and put a 3-letter code like USD or KRW in priceCurrency.
  • Markup must match what users can see; marking up hidden FAQs or reviews can lead to manual actions.
  • Group entities in @graph and link them with @id to avoid duplication.

Frequently Asked Questions

Is it the same as Google's Rich Results Test?

No. It is a pre-check of required / recommended properties and formats for common types. Verify with the Rich Results Test and the Schema.org validator before release.

Does it check Microdata or RDFa?

Only JSON-LD, which is also Google's recommended format; consider moving Microdata to JSON-LD.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
